# 맥에서 한/영을 빨리 두 번 누르면 받아쓰기 창이 뜨던 문제

What changed in ko.27
- **The controlled Mac no longer sends an Fn key when it switches the input source.** On a Mac controlled through RustDesk, each arriving 한/영 key (F18, Hangul, LANG1) posts that Mac's own "previous input source" shortcut. Up to ko.26 the app then posted an extra Fn key event to clear the Fn flag that F18 leaves set; macOS counted it as an Fn press, so two 한/영 presses close together looked like "Fn twice" and opened the 받아쓰기 (Dictation) prompt. The shortcut's key-up now carries the cleared state and nothing else is posted. The input source still switches once per press.
- **Caps Lock counts as 한/영 from a remote window's first focus.** On a controlling Mac with "Caps Lock 키로 ABC 입력 소스 전환" on, the first focus could read that setting as unreadable and send Caps Lock as a plain key once; the setting is now read when the remote window opens.
- Both macOS apps ("RustDesk (for korean)" and "RustDesk (forked ranode)") carry both changes. Windows, Linux and Android are rebuilt from the ko.27 commit with no change since ko.26.
